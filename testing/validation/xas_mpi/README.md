## Prepare and submit

Prepare the four independent seeds exactly once:

```bash
cd "${XAS_MPI_PACKAGE_ROOT}"
bash scripts/prepare_runs.sh
```

`submit_all.sh` then performs a complete preflight before the first `sbatch`:
it requires the expected clean source commit and executable, verifies every
fixture and prepared seed checksum, and rejects missing, completed, failed, or
otherwise contaminated run directories. If preparation or any prerequisite
check fails, no job is submitted.

Set the site allocation values and submit:

```bash
export SLURM_ACCOUNT=YOUR_ACCOUNT
export SLURM_PARTITION=dc-cpu
export SLURM_TIME=00:10:00
export FLEUR_SOURCE_DIR=/path/to/clean/fleur
export FLEUR_BIN="${FLEUR_SOURCE_DIR}/build.xas_mpi_b3818dad/fleur_MPI"
bash scripts/submit_all.sh
```

Equivalent individual commands, issued from the package root, are:

```bash
export XAS_MPI_PACKAGE_ROOT="$PWD"
sbatch --account="${SLURM_ACCOUNT}" --partition="${SLURM_PARTITION}" --time="${SLURM_TIME}" \
  --chdir="$PWD" --export=ALL,XAS_MPI_PACKAGE_ROOT="$PWD",FLEUR_BIN="${FLEUR_BIN}",FLEUR_SOURCE_DIR="${FLEUR_SOURCE_DIR}" scripts/run_np1.slurm
sbatch --account="${SLURM_ACCOUNT}" --partition="${SLURM_PARTITION}" --time="${SLURM_TIME}" \
  --chdir="$PWD" --export=ALL,XAS_MPI_PACKAGE_ROOT="$PWD",FLEUR_BIN="${FLEUR_BIN}",FLEUR_SOURCE_DIR="${FLEUR_SOURCE_DIR}" scripts/run_np2_pure.slurm
sbatch --account="${SLURM_ACCOUNT}" --partition="${SLURM_PARTITION}" --time="${SLURM_TIME}" \
  --chdir="$PWD" --export=ALL,XAS_MPI_PACKAGE_ROOT="$PWD",FLEUR_BIN="${FLEUR_BIN}",FLEUR_SOURCE_DIR="${FLEUR_SOURCE_DIR}" scripts/run_np4_pure.slurm
```

The wrappers use `XAS_MPI_PACKAGE_ROOT`, not `BASH_SOURCE[0]`, to find the run

## Recorded provenance

Each job writes `job_environment_<jobid>.log` before execution and records:

- clean commit and `git status --short` result;
- executable path, SHA256, stat/build time, and `fleur_MPI -version` output;
- input and original pre-run restart checksums;
- module list and compiler, MPI, MKL, HDF5, CMake, and libxml2 information;
- hostname, Slurm variables and job ID;
- MPI ranks, one OpenMP thread, and requested `pe_per_kpt`;
- exact `srun` command and timestamps;
- relevant dynamic libraries;
- post-run restart and result checksums.

The job aborts before FLEUR if the source is dirty, the commit or restart hash
is wrong, or previous output is present.

## Expected output

Each `runs/<label>/` directory contains:

- `RUN_COMPLETE`;
- `fleur_stdout.log`, `fleur_stderr.log`, and `job_environment_<jobid>.log`;
- `out`, `out.xml`, timing and usage files;
- `xas_mpi_L3_{x,y,z}_eta0p030.dat`;
- one `xas_mpi_L3_<pol>_transitions_rankNNNN.dat` per global rank;
- `result_sha256.txt`.

Valid subgroup collaborators in `np4_shared` retain normal header-only
transition files. They must not be deleted.

## Mandatory checkpoint and comparator

After all four jobs finish, run the layout-only checkpoint before promoting a
reference:

```bash
cd "${XAS_MPI_PACKAGE_ROOT}"
python3 scripts/compare_xas_mpi.py --skip-reference | tee xas_mpi_checkpoint.txt
```

This retains the established tolerances:

- grid maximum absolute difference `< 1e-12` Ha;
- spectrum and additive-value comparison passes when maximum absolute
  difference `< 1e-12` or relative difference `< 1e-10`;
- transition arithmetic absolute `< 1e-18` or relative `< 1e-12`;
- no spectral value below `-1e-14`.

It also requires successful logs, the exact requested layouts, 2810 transitions
per polarization, no duplicate discrete keys, full k-point coverage 1--27,
parent-star coverage 1--6, parent/star weights of one, equal transition-key
sets, invariant weighted-strength sums and additive diagnostics, equal
underflow counts, and the expected header-only shared-rank files.

For a future reference regeneration, stop after this checkpoint and return the
complete package results for review. Do not replace `reference/canonical/`
from an unreviewed or dirty-tree run.

## Canonical versus historical reference

The canonical acceptance reference is the approved clean JURECA np1
calculation built from the Phase-1 commit with the controlled module
environment above. Its complete machine-readable provenance is in
`provenance/clean_jureca_manifest.json`.

The July 2026 macOS spectra are legacy provenance only. The automatic XAS
energy window is derived from numerical transition extrema. Tiny compiler- and
platform-dependent endpoint changes can therefore produce a tiny affine energy
grid change. Cross-platform historical data must not be used as a canonical
bytewise reference or as a reason to weaken acceptance tolerances.
